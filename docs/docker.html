GOML con Docker

GOML se puede usar de dos formas: sin Docker (PostgreSQL, Node.js y OpenSSL instalados en tu equipo, ver Instalación) o con Docker, donde todo viene empaquetado y solo necesitas Docker. Esta página explica la segunda. Copia cada bloque y síguelos en orden.

1. Requisitos 2. Archivo .env 3. Arrancar 4. Uso diario 5. Consideraciones 6. Backup 7. Restaurar 8. Cambiar de modo 9. Empezar de cero
Terminal · paso 1

1Verificar Docker

Necesitas Docker Engine y el plugin Compose. No hace falta instalar Node.js, PostgreSQL ni OpenSSL en tu equipo: todo eso va dentro de los contenedores. Si no tienes Docker, sigue la guía oficial en docs.docker.com/engine/install.

docker --version docker compose version Ambos comandos deben mostrar una versión.
Terminal · paso 2

2Crear el archivo .env

Toda la configuración se hace en un archivo .env en la raíz del proyecto (donde está docker-compose.yml). Parte desde la plantilla y ajusta estos valores: HOST_IP (la IP de tu equipo en la red, sale con hostname -I), DB_PASSWORD (elígela ahora, antes del primer arranque) y OWNER_USER / OWNER_PASSWORD.

cp .env.example .env hostname -I nano .env 192.168.1.50
Terminal · paso 3

3Construir y arrancar

La primera vez Docker construye la imagen de GOML (tarda unos minutos). Al arrancar, el contenedor crea las tablas, crea el propietario si la base está vacía y genera el certificado HTTPS con tu HOST_IP. Después abre en el navegador https://TU_IP:3000. El navegador avisará que el certificado no es de confianza porque es autofirmado; es lo esperado en una LAN.

docker compose up -d --build docker compose ps docker compose logs -f goml ✓ Estructura de la base de datos lista.
✓ Propietario "admin" creado.
Terminal · paso 4

4Uso diario y actualizaciones

Estos son los comandos de todos los días. Detener o reiniciar no borra nada. Para actualizar GOML a una versión nueva del código, descárgala y reconstruye la imagen: tus datos se conservan porque viven en volúmenes aparte.

docker compose stop docker compose start docker compose restart goml docker compose down git pull docker compose up -d --build down quita los contenedores pero conserva los datos. Con down -v se borran (ver paso 9).
Consideraciones · paso 5

5Cosas que debes saber

  • Dónde están tus datos: en tres volúmenes de Docker: pgdata (base de datos), gomldata (juegos, avatares y clave de sesión) y gomlcerts (certificados). No los toques a mano: usa el backup del paso 6.
  • Cuidado con docker compose down -v: la opción -v borra los volúmenes y con ellos toda tu base de datos y tus juegos. Úsala solo si quieres empezar de cero (ver paso 9), y siempre después de hacer un backup.
  • DB_PASSWORD se fija en el primer arranque. Si después editas el .env, la base ya creada conserva la contraseña antigua y GOML no podrá conectarse.
  • OWNER_USER y OWNER_PASSWORD solo se usan si la base no tiene usuarios. Cuando restauras un backup, el propietario viene dentro del backup.
  • Si cambia la IP de tu equipo: el certificado solo se genera una vez. Actualiza HOST_IP en el .env, borra el volumen de certificados y vuelve a arrancar: docker compose down, luego docker volume ls para ver el nombre (termina en gomlcerts), docker volume rm NOMBRE y docker compose up -d.
  • Puertos: se publican APP_PORT (3000) y GAMES_PORT (3001). Si usas firewall, permítelos, por ejemplo sudo ufw allow 3000/tcp. La base de datos no se expone fuera de Docker.
  • No ejecutes las dos versiones a la vez (con y sin Docker) en el mismo equipo: usan los mismos puertos.
  • Inicio automático: los contenedores tienen restart: unless-stopped, así que vuelven a levantar solos al reiniciar el equipo (mientras el servicio Docker esté activo).
  • Acceder a la base: si necesitas entrar a PostgreSQL, docker compose exec db psql -U goml -d goml_db (usa el DB_USER y DB_DATABASE de tu .env).
Terminal · paso 6

6Respaldar con Docker

El respaldo sigue siendo el mismo de siempre: base de datos más carpeta data. Se hace con GOML funcionando, desde la carpeta del proyecto. Los dos archivos resultantes son todo lo que necesitas llevar a otro equipo. No hace falta respaldar los certificados: se regeneran solos.

docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc --no-owner --no-acl' > goml_db.dump docker compose exec -T goml tar czf - -C /app data > data_backup.tar.gz Se crean goml_db.dump y data_backup.tar.gz en la carpeta actual.
Terminal · paso 7

7Restaurar con Docker en otro equipo

En el equipo destino necesitas Docker, el proyecto (docker-compose.yml y .env con el HOST_IP de ese equipo) y los dos archivos del respaldo. Si no clonaste el repositorio y llevas la imagen como archivo, primero cárgala con docker load. El orden importa: la base se restaura antes de arrancar GOML, para que no cree un propietario nuevo.

docker compose up -d db docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner' < goml_db.dump docker compose create goml docker compose run --rm --no-deps -T --entrypoint tar goml xzf - -C /app < data_backup.tar.gz docker compose up -d Abre https://TU_IP:3000 e inicia sesión con tus usuarios de siempre.
Terminal · paso 8

8Pasar de sin Docker a Docker

El archivo .dump de la base es compatible entre ambos modos. Lo único que cambia es la carpeta data: la guía de backup sin Docker la guarda en ZIP, y la restauración con Docker espera un .tar.gz. Conviértela y sigue el paso 7 con tu goml_db.dump original.

unzip data_backup.zip tar czf data_backup.tar.gz data Ahora sigue el paso 7 con goml_db.dump y data_backup.tar.gz.

En sentido contrario (Docker a sin Docker): extrae la carpeta data con tar xzf data_backup.tar.gz y colócala junto a app.js. La base se restaura siguiendo los pasos de la guía de backup sin Docker, usando el goml_db.dump generado en el paso 6.

Terminal · paso 9

9Empezar de cero

Si quieres dejar GOML como recién instalado (sin usuarios, sin juegos y con una base nueva), hay que borrar los volúmenes. Esto es irreversible: se pierden la base de datos, los juegos, los avatares y los certificados. Si hay algo que quieras conservar, haz antes el backup del paso 6.

docker compose down -v docker compose up -d docker compose logs -f goml ✓ Estructura de la base de datos lista.
✓ Propietario "admin" creado.

El comando down -v detiene GOML y borra los tres volúmenes (pgdata, gomldata y gomlcerts). Al volver a arrancar, GOML crea las tablas, genera un certificado nuevo y crea el propietario con el OWNER_USER y OWNER_PASSWORD de tu .env, así que revísalos antes. Como la base queda vacía, este también es el momento en que puedes cambiar DB_PASSWORD en el .env y que funcione.

Si solo quieres borrar una parte, apaga con docker compose down, mira los nombres con docker volume ls y borra únicamente el que necesites con docker volume rm NOMBRE. Los nombres llevan el prefijo de la carpeta del proyecto y terminan en pgdata, gomldata o gomlcerts. Ojo: borrar solo la base o solo data deja el sistema inconsistente (juegos sin registro, o registros sin archivos). Para empezar de cero, borra ambos.
